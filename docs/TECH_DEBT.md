# Technical Debt

> **Last updated**: 2026-06-18
>
> This file tracks implementation deviations from the known-correct shape. It is not a product backlog.
>
> ### Admission Criteria
>
> Record an item only when all conditions are true:
>
> - The current implementation differs from a known better shape
> - The deviation has concrete engineering impact
> - There is a plausible repayment path
>
> Examples that belong here: dead code/columns, wrong abstraction, latent footgun, missing quality gate, known behavior bug.
>
> Do not record product gaps, deferred features, vague improvement ideas, or operational follow-ups. Put those in `BACKLOG.md` instead.
>
> Remove rows when debt is repaid. Historical evidence belongs in git and completed plans.
