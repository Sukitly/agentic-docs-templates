# Backlog

> **Last updated**: 2026-06-18
>
> This file tracks product gaps, deferred decisions, and operational/security follow-ups. It is distinct from `TECH_DEBT.md`.
>
> ### Scope
>
> Record an item when it is a capability or follow-up that should exist but is not currently scheduled.
>
> - ✅ Include: deferred product capability, operational/security follow-up, restartable decision with trigger conditions
> - ❌ Exclude: dead code, wrong abstraction, implementation bug, missing quality gate → use `TECH_DEBT.md`
> - ❌ Exclude: work already tracked by an active Exec Plan
>
> When an item starts, convert it into a Design Doc / Exec Plan if the criteria are met and remove it from this table. If an item is abandoned, remove it and record a decision in `DECISIONS.md` only if the abandonment constrains future work.
